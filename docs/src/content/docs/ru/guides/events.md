## Подписка

```rust
#[event]
fn on_join(e: PlayerJoined) -> Result<()> {
    log::info(format!("{} зашёл на {}", e.player.label(), e.ctx.server_name()));
    Ok(())
}
```

Имени события нет нигде. `#[event]` читает его из типа аргумента — поэтому
[каталог событий](../../reference/events/) и показывает рядом с каждым именем структуру:
эта структура **и есть** то, чем подписываются.

### Сообщения из веб-сокета: WebMessage

Когда игрок взаимодействует с вашим веб-мини-аппом и отправляет действия через сокет с помощью `noro.ws.send(...)`, мастер направляет их прямо в ваш модуль в виде события `WebMessage`:

```rust
#[event]
fn on_web_action(e: WebMessage) -> Result<()> {
    log::info(format!("Действие от {}: {:?}", e.player.label(), e.payload));
    Ok(())
}
```

Подробнее о работе в реальном времени читайте в отдельном руководстве [Веб-сокеты и Realtime](../websockets/).

## Где событие случилось

Каждое событие несёт `EventCtx`. На инстансе с несколькими сборками событие без него почти
бесполезно: вы знаете, что игрок зашёл, но не знаете куда.

```rust
#[event]
fn on_rename(e: UserRenamed) -> Result<()> {
    if e.ctx.from_game() { return Ok(()) }            // пришло из игры
    if e.ctx.caused_by("my-module") { return Ok(()) } // наше собственное эхо
    Ok(())
}
```

| Поле | Что говорит |
|---|---|
| `origin` | `Game` · `Web` · `Launcher` · `Cli` · `Module(id)` · `System` — *через что* |
| `actor` | человек, модуль или токен за этим — *кто* |
| `server_id`, `server_slug` | сборка; `None` у глобальных событий вроде регистрации |
| `game_server_id` | конкретный игровой сервер, если пришло из игры |
| `at` | когда |
| `depth` | насколько глубоко вложены публикации |

:::caution[Следите за собственным эхом]
Если обработчик меняет те же данные, за которыми следит, изменение публикует событие,
которое будит его снова. Защита — `ctx.caused_by("ваш-id")`. Мастер к тому же перестаёт
публиковать, когда `depth` упирается в потолок, но это страховка, а не замысел.
:::

## Приоритеты

Обработчики одного события идут лесенкой — той же, что привычна по Bukkit: решающие после
наблюдающих.

```rust
#[event(priority = high)]
fn decide(e: BankPreTransfer) -> Result<()> { Ok(()) }
```

`lowest` → `low` → `normal` (по умолчанию) → `high` → `highest` → `monitor`. `monitor` —
только для наблюдателей: отмена от него игнорируется.

## Сказать нет

Обработчик `Pre` берёт событие по `&mut` — и это всё объявление. Ссылка и говорит мастеру,
что вашего ответа стоит подождать и вернуть его обратно:

```rust
#[event]
fn rename(e: &mut UserPreRename) -> Result<()> {
    if reserved(&e.new_name) {
        e.stop("mod-gate-name-reserved");
        return Ok(());
    }
    // Правки едут назад. Мастер запишет то имя, которое вы здесь оставили.
    e.new_name = e.new_name.to_lowercase();
    Ok(())
}
```

`stop` принимает **ключ Fluent**, а не готовый текст: читать его будет игрок, а собрать
предложение может только та сторона, которая знает его язык.

Обработчики идут по приоритету, и каждый получает событие таким, каким его оставил
предыдущий: комиссия одного модуля ложится на сумму, уже исправленную другим, а не на
исходную.

:::note[Где срабатывает каждое]
Доставляются все девять `Pre`. Два стоит знать точно:

`player.pre_join` спрашивается, только когда мастер и сам готов пустить, — подтверждать
бан от вас не нужно, — и только при одиночном запросе, никогда для ростера целиком.
Отказ превращается в отказ агента, а причиной становится ваш ключ.

`user.pre_role_granted` срабатывает на выдаче **из панели**. Роль, выданная другим
модулем, через него не проходит: межмодульных запретов эта граница не предлагает.

`player.pre_chat` — единственное событие, за которое игровой сервер платит на каждом
сообщении, поэтому мастер сообщает агенту, есть ли подписчики, и без них агент молчит.
Бюджет здесь **700 мс** со стороны игрового сервера, а не секунда: игрок уже нажал Enter и
смотрит, появится ли его строка. Дальше сообщение уходит как есть.

Правка `text` работает на Paper. На Fabric и Forge тамошний хук отвечает «да или нет» и
больше ничем — отказ доедет, правка нет. Пишите фильтр так, чтобы отказ был запасным
поведением, а не неожиданностью.
:::

### Что обработчик Pre обязан знать

Он стоит **на пути живого запроса**. Мастер ждёт, а вместе с ним ждёт человек — поэтому
бюджет здесь секунда, пятая часть от того, что есть у `Post`. Работа длиннее относится к
`Post`.

Он выполняется *до* открытия транзакции мастера, и состояние между ними может измениться.
Всё, что обязано выполняться на момент записи, перепроверяется под блокировкой строки:
поднятая сумма перевода денег не создаёт, потому что баланс отправителя проверяется ещё
раз уже внутри транзакции.

А если модуль медленный, упал или ответил мусором, действие **проходит**. Один сломанный
модуль не должен закрывать дверь всем — это та поломка, которую находят в три часа ночи.
Отказ обязан быть решением, а не побочным эффектом.

## Свои события

Каталог — это то, что объявляет платформа. Ваш модуль может объявлять тоже, и тогда второй
модуль отреагирует, не зная о первом ничего.

```rust
// в модуле магазина
events::emit("purchase", json!({ "player": id.to_string(), "item": "vip" }))?;
```

```rust
// в каком-то другом модуле
#[event("mod.shop.purchase")]
fn on_purchase(e: serde_json::Value) -> Result<()> { … }
```

Вы передаёте последнюю часть имени, а мастер публикует его как `mod.<ваш-id>.<имя>`.
Префикс именно добавляется, а не принимается на веру, и по той же причине, по которой его
несут ключи локалей: иначе модуль опубликовал бы `player.banned`, и каждый обработчик
настоящего события ему поверил бы.

`emit_on(name, server_id, payload)` привязывает событие к сборке — без этого до модулей с
областью «сборка» оно не дойдёт.

### Кольца

Модуль A объявил, B отреагировал и объявил, A отреагировал на это. Само по себе оно
крутится, пока кто-нибудь не заметит нагрузку.

Каждое событие несёт глубину вложенности. Событие, выпущенное из обработчика, наследует её
и прибавляет единицу, а после потолка в три мастер публиковать отказывается — вы получите
ошибку, а не тишину: модуль, случайно построивший кольцо, должен узнать об этом из вызова,
а не из графика.

Вторая половина за вами. Прежде чем на что-то реагировать, спросите, не вы ли это сделали:

```rust
if e.ctx.caused_by("my-module") { return Ok(()) }
```

### Чего публикация не делает

Обработчики выполняются после того, как ваш вызов вернулся, а не во время него. `emit`
отдаёт событие мастеру и сразу возвращается — ровно как `Post` у самой платформы. Узнать
из него, обработал ли кто-нибудь что-нибудь, нельзя, и упавший обработчик ваш вызов не
роняет.

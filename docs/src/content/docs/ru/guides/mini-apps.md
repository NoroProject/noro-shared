Модуль может привезти свой интерфейс. Объявите его в манифесте — и он появится разделом в
админке, на подсайте сборки или в кабинете игрока.

```toml
[[apps]]
placement = "cabinet"      # admin | hub | cabinet | widget
kind = "vue"               # vue | page
entry = "app.js"
title = "mod-my-module-title"
icon = "i-lucide-gift"
```

## Куда он может попасть

| `placement` | Где появляется |
|---|---|
| `admin` | раздел в админке |
| `cabinet` | страница в кабинете игрока |
| `hub` | раздел подсайта сборки, по адресу `/s/<slug>/m/<ваш-id>` |
| `widget` | блок внутри чужой страницы — см. ниже |

Разделы подсайта показываются той сборке, которой принадлежат. У модуля с областью «сборка»
раздел будет на своём подсайте, а не на соседнем.

### Виджеты

Виджет встаёт в **именованный слот** страницы, которая принадлежит панели. Слот называют в
манифесте:

```toml
[[apps]]
placement = "widget"
slot = "cabinet.home.cards"
kind = "vue"
entry = "widget.js"
title = "mod-my-module-widget"
```

Список слотов закрытый:

| Слот | Где это |
|---|---|
| `admin.user.panel` | карточка игрока в админке |
| `hub.feed.aside` | колонка рядом с лентой подсайта |
| `cabinet.home.cards` | главная кабинета, после её собственных карточек |

Закрытый намеренно. Открытый сделал бы вёрстку каждой страницы публичным контрактом:
передвиньте блок — и чей-то виджет переедет вместе с ним туда, куда его никто не
проектировал. Новый слот заводят осознанно и вместе с обещанием, что он останется.

Слот без виджетов не рисует ничего: ни рамки, ни заголовка. У большинства страниц их нет,
и полоска «здесь могло быть расширение» на каждой — это шум.

## Два вида

| `kind` | Как работает | Когда брать |
|---|---|---|
| `vue` | компонент Vue, который панель монтирует в своё дерево | обычный случай |
| `page` (по умолчанию) | статическая страница в песочнице, разговор через `postMessage` | когда изоляция важнее удобства |

`page` стоит по умолчанию, потому что изоляцию нельзя терять из-за забытого поля. `vue` —
то, что обычно нужно: он получает компоненты панели и её вид, а бандл весит пару килобайт.

## Как писать мини-апп на Vue

Обычный Vue с обычными типами:

```vue
<script setup lang="ts">
import { AtomBadge, EmptyState, NoroCard, useNoro } from '@noroproject/module-ui'
import { onMounted, ref } from 'vue'

const noro = useNoro()
const points = ref<number | null>(null)

onMounted(async () => {
    points.value = await noro.api<number>('/me')
})
</script>

<template>
    <NoroCard icon="i-lucide-gift" :title="noro.t('mod-my-module-title', 'Награды')">
        <EmptyState v-if="points === null" icon="i-lucide-loader" title="Загрузка" bare />
        <AtomBadge v-else tone="success">{{ points }}</AtomBadge>
    </NoroCard>
</template>
```

```bash
bun add -d @noroproject/module-ui
```

Это собственные компоненты панели, поэтому страница похожа на остальной интерфейс без
единой строки стилей.

## Что даёт `useNoro()`

Коротко — ниже; полностью, с каждым полем, — в [API мини-аппа](../../reference/mini-app-api/).

```ts
const noro = useNoro()
```

| | |
|---|---|
| `api(path, options?)` | зовёт **ваши** ручки и ничьи больше — адрес собирает панель |
| `t(key, fallback?)` | ваши ключи локалей |
| `user` | тот, кто открыл страницу, или `null` |
| `notify.ok()` / `notify.fail(e)` | собственные уведомления панели |
| `navigate(path)` | переход внутри панели |
| `can(node)` · `canAny([…])` · `canOn(node, serverId)` | что позволено смотрящему |
| `confirm({ title, text?, danger? })` | спрашивает диалогом панели |
| `format.duration` · `money` · `date` · `ago` | форматирование панели. `duration` принимает **секунды** — ту единицу, которой говорит мастер, — и читает их вплоть до секунды |
| `paged(path, opts?)` | страничный список из вашей ручки |
| `platform.*` | чтения данных платформы |

### Что показывать

```ts
const canReset = noro.can('noro.module.shop.manage')
```

Тот же сопоставитель, которым панель рисует свои меню, вместе с шаблонами: `noro.admin.*`
отвечает «да» на `noro.admin.modules.view`. Это решает, что **показать**; что позволить,
решает мастер, а `auth` вашей ручки проверяет ещё раз у себя. Спрятанная кнопка — вежливость,
а не граница.

### Спросить перед тем, как делать

```ts
if (!await noro.confirm({ title: 'Обнулить очки?', text: 'Это необратимо.', danger: true })) {
    return
}
```

Диалог рисует панель, поэтому он выглядит как любой другой и не может быть закрыт вашей же
вёрсткой. Отказ — да и просто закрытие — даёт `false`, так что неотвеченный вопрос читается
как «нет», а не как исключение, которое надо ловить.

### Страничные списки

```ts
const list = noro.paged<Order>('/orders', { perPage: 25 })
await list.load()
```

Ваша ручка отвечает `{ items, total }` — так отвечает каждый список этой платформы, — а вы
получаете ссылки, которые сразу кладутся в шаблон, с отложенным поиском и состоянием
страницы. `list.refresh()` перечитывает текущую страницу после вашей же правки.

### Чтения платформы

```ts
const me = await noro.platform.me.profile()
const servers = await noro.platform.servers.list()
const feed = await noro.platform.hub.feed('survival', 1)
```

Функции, а не адреса. Ручки панели — её собственное дело: модуль, собранный против
`/api/me/hubs`, сломался бы в день, когда этот путь изменится, поэтому обещана вот эта
поверхность. На то, чего пакет ещё не назвал, есть `platform.call(method, args)`.

Всё здесь — **чтение**. Запись идёт через вашу же ручку на Rust, где проверяются выданные
оператором возможности: запись отсюда уехала бы под токеном того, кто просто открыл
страницу.

Оба вида мини-аппа получают одинаковую поверхность. Страница в песочнице достаёт её через
мост, а не ходит сама, — поэтому адреса остаются вне песочницы, а правильной надо держать
одну реализацию.

### Сборка

`vue` и `@noroproject/module-ui` обязаны быть **внешними** и отображаться в глобали,
которые публикует панель:

```js
export default defineConfig({
    plugins: [vue()],
    build: {
        outDir: 'web',
        lib: { entry: 'ui/app.js', formats: ['iife'], name: '__noroModuleExport', fileName: () => 'app.js' },
        rollupOptions: {
            external: ['vue', '@noroproject/module-ui'],
            output: { globals: { vue: '__noroVue', '@noroproject/module-ui': '__noroUi' } },
        },
    },
})
```

Это не оптимизация размера — вернее, не в первую очередь она. Своя копия Vue в бандле дала
бы вашему компоненту собственный экземпляр реактивности, и панель не смогла бы смонтировать
его в своё дерево вовсе. В шаблоне этот конфиг уже правильный.

## Что обещает контракт

В `@noroproject/module-ui` лежат только объявления типов — реализации принадлежат панели.
Перечисленные там компоненты и пропсы будут работать и дальше: у панели есть проверка
времени компиляции, утверждающая, что её настоящие компоненты по-прежнему удовлетворяют
каждому обещанию пакета, и её typecheck падает с именем нарушенного пропса, если перестают.

Что вы получаете: `NoroCard`, `EmptyState` и атомы `AtomBadge`, `AtomButton`,
`AtomCheckbox`, `AtomChip`, `AtomInput`, `AtomModal`, `AtomNumberInput`, `AtomSegmented`,
`AtomSelectMenu`, `AtomToggle`.

## Страницы в песочнице

С `kind = "page"` вы привозите обычный HTML и разговариваете с панелью через мост, который
отдаёт мастер:

```html
<script src="/api/modules/bridge.js"></script>
<link rel="stylesheet" href="/api/modules/noro-ui.css" />
<script>
    noro.ready(async (ctx) => {
        const points = await noro.call('/me')
        document.body.textContent = `${points}`
    })
</script>
```

`noro.ready(fn)` — функция, а не событие, и это намеренно: быстро загрузившаяся страница
иначе пропустила бы параметры запуска целиком.

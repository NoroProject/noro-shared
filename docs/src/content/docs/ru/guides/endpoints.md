---
title: Свои ручки
description: Как объявить маршрут, кого пускать и что приходит в обработчик.
---

Модуль может отвечать по HTTP под своим префиксом. С этими ручками разговаривает ваш
мини-апп — и всё остальное, что вы на них направите.

```rust
#[route(GET, "/me")]
fn me(req: HttpRequest) -> Result<Points> {
    let id = req.require_user()?;
    Ok(Points {
        points: store::user(id).get_or::<i64>("points")?,
    })
}
```

Это отвечает на `GET /api/modules/<ваш-id>/me`. Тип возврата должен только
сериализоваться; остальное делает мастер.

## Кого пускать

```rust
#[route(POST, "/buy", auth = permission("noro.module.shop.buy"))]
fn buy(req: HttpRequest) -> Result<Receipt> { … }
```

| `auth` | Кто проходит |
|---|---|
| `user` (по умолчанию) | любой вошедший игрок |
| `public` | кто угодно, включая невошедших — для приёма вебхуков |
| `permission("node")` | игрок с этим правом |
| `admin("node")` | админ-токен или сотрудник с этим правом |

`user` по умолчанию не случайно: публичную ручку надо попросить, она не должна получаться
из забытого аргумента.

**Не перепроверяйте права в обработчике.** Мастер сверил их с объявленным до вызова —
запрос, который не проходит, до вас не доезжает. Повторная проверка означает лишь два
места, которые надо держать в согласии.

Узлы прав, которыми вы пользуетесь, обязаны быть объявлены в манифесте и начинаться с
`noro.module.<id>.` — это и держит ваши узлы вне чужой ветки, и заводит их в подсказки
редактора ролей.

## Что приходит

```rust
pub struct HttpRequest {
    pub method: String,
    pub path: String,
    pub query: Value,           // строка запроса одним объектом
    pub body: Option<Value>,
    pub user: Option<Uuid>,     // пусто только у публичной ручки
}
```

Помощники: `req.json::<T>()` для тела, `req.param("name")` для параметра строки запроса,
`req.require_user()`, когда ручке нужен вошедший.

### Декларативные экстракторы

Вместо ручного разбора `HttpRequest` аргументы метода можно объявлять прямо через типизированные экстракторы:

```rust
#[route(POST, "/claim")]
fn claim(AuthUser(user): AuthUser, Json(body): Json<ClaimReq>) -> Result<Receipt> {
    // `user` — гарантированный Uuid; `body` — разобранный `ClaimReq`
    Ok(Receipt { id: user })
}
```

Доступные экстракторы (в `noro_sdk::prelude::*`):
- `AuthUser(pub Uuid)` — извлекает ID вошедшего пользователя или сразу возвращает ошибку неавторизованного доступа
- `OptionalUser(pub Option<Uuid>)` — опциональный ID пользователя (если запрос авторизован)
- `Json<T>(pub T)` — парсит JSON-тело запроса в тип `T`
- `QueryParams<T>(pub T)` — парсит параметры query-строки в тип `T`
- `RawParams(pub Value)` — даёт доступ к сырому объекту параметров query
- `HttpRequest` — полный объект запроса

## Пользовательские HTTP-статусы и заголовки (`HttpResponse`)

По умолчанию возврат сериализуемой структуры отдаёт `200 OK` с `application/json`.
Если нужно вернуть другой статус, перенаправление или свои заголовки, возвращайте `HttpResponse`:

```rust
#[route(POST, "/item")]
fn create_item() -> Result<HttpResponse> {
    Ok(HttpResponse::new(201, json!({ "created": true }))
        .with_header("X-Custom-Header", "value"))
}

#[route(GET, "/legacy")]
fn legacy() -> Result<HttpResponse> {
    Ok(HttpResponse::redirect("/api/modules/shop/v2/items"))
}
```

HTTP разбирает сам мастер: заголовков и кук здесь нет, а решение о допуске уже принято.

## Ошибки

Верните `Err(ModuleError)`, и мастер превратит это в нормальный ответ:

```rust
return Err(ModuleError::not_found("такого лота нет"));
```

| Конструктор | Значит |
|---|---|
| `ModuleError::not_found(…)` | объекта нет |
| `ModuleError::invalid(…)` | аргументы не проходят |
| `ModuleError::conflict(…)` | состояние не позволяет — не хватает денег, дубль |

Паника ловится и становится сбоем модуля: мастер не падает, но модулю засчитывается
промах. Десять сбоев за пять минут — и он выключается сам.

## Один путь — один обработчик

Объявить одинаковые метод и путь дважды нельзя: это отвергается при установке. «Какой из
них сработает» — вопрос без хорошего ответа, поэтому ему не дают возникнуть.

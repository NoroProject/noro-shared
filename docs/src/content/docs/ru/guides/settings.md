Модулям часто требуются настраиваемые параметры: ставка налога, интервал выплат, флаги включения функций, секретные ключи API или название внутриигровой валюты. Пересобирать модуль ради изменения одного числа неудобно.

Платформа Noro предоставляет декларативные настройки через `#[derive(Settings)]`. Вы описываете типизированную структуру конфигурации на Rust, а мастер автоматически создаёт интерактивную форму в панели управления и сохраняет значения в изолированном хранилище модуля.

## Объявление настроек

Добавьте к структуре конфигурации производные макросы `Settings`, `Serialize`, `Deserialize` и `Default`:

```rust
use noro_sdk::prelude::*;

#[derive(Settings, Serialize, Deserialize, Default)]
pub struct ModuleConfig {
    #[setting(label = "mod-rewards-enabled")]
    pub enabled: bool,

    #[setting(label = "mod-rewards-interval")]
    pub reward_interval_secs: i64,

    #[setting(label = "mod-rewards-currency")]
    pub currency_name: String,
}
```

### Поддерживаемые типы полей

Макрос `#[derive(Settings)]` анализирует типы полей Rust и сопоставляет их с элементами интерфейса панели:

| Тип поля | Элемент интерфейса | Описание |
|---|---|---|
| `bool` | Переключатель (Toggle) | Булев переключатель «вкл/выкл» |
| `i64`, `u64`, `i32`, `u32`, `f64` | Числовое поле (Number) | Ввод числовых значений |
| `String` (или другие) | Текстовое поле (Text) | Однострочный ввод текста |

### Атрибуты полей

- **`label = "ключ"`**: Указывает ключ перевода Fluent для заголовка поля в панели управления. Если атрибут опущен, отображается имя поля Rust.

## Регистрация настроек в модуле

Чтобы мастер и веб-панель узнали о доступных настройках, зарегистрируйте структуру внутри блока `#[noro::module]` с помощью хука `#[register]`:

```rust
#[noro::module]
impl RewardsModule {
    #[register]
    fn register(reg: &mut Registration) {
        ModuleConfig::register(reg);
    }

    // Другие обработчики (события, ручки, задачи, RPC)...
}
```

Метод `ModuleConfig::register(reg)` передаёт список полей и их типы в манифест регистрации модуля при загрузке.

## Чтение настроек в коде

Вызывайте `ModuleConfig::load()?` в любом месте, где требуются актуальные параметры:

```rust
#[task("5m")]
fn distribute_rewards() -> Result<()> {
    let cfg = ModuleConfig::load()?;

    if !cfg.enabled {
        return Ok(());
    }

    log::info(format!(
        "Выплата наград в валюте: {}",
        cfg.currency_name
    ));

    // Логика начисления наград...
    Ok(())
}
```

### Как работает `load()`

1. Метод считывает каждое поле по имени ключа из `store::instance()`.
2. Если оператор сохранил значение в панели управления, возвращается сохранённое значение.
3. Если значение ещё не было настроено, `load()` возвращает значение по умолчанию из `Self::default()`.

Поскольку значения читаются из `store::instance()`, любые изменения, сделанные оператором в панели управления, вступают в силу при следующем же вызове `load()` — без перезапуска модуля или сервера.

## Опыт оператора

Когда оператор открывает страницу модуля в панели управления (**Модули** → выбор модуля):

1. Отображается вкладка **«Настройки»** с автоматически сгенерированными полями.
2. Подписи полей переводятся на язык оператора с использованием файлов Fluent модуля (`locales/en.ftl`, `locales/ru.ftl`).
3. При сохранении формы новые значения записываются в хранилище инстанса.

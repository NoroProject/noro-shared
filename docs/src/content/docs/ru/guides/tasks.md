```rust
#[task("1h")]
fn payout() -> Result<()> {
    for p in roster::online()? {
        bank::transfer(server, treasury, account_of(p)?, 100, "почасовое")?;
    }
    Ok(())
}

// Или через 5-позиционное cron-выражение:
#[task(cron = "0 4 * * *")]
fn daily_payout() -> Result<()> {
    // выполняется каждый день в 04:00 UTC
    Ok(())
}
```

Расписание может быть интервалом (`30s`, `5m`, `1h`, `2d`) или cron-выражением (`cron = "0 4 * * *"`). Оно проверяется при установке модуля,
так что опечатку отвергнут сразу.

## Интервалы и Cron

- **Интервалы (`every = "1h"`):** Запуск через каждый час работы мастера, отсчитывая от времени старта.
- **Cron-выражения (`cron = "0 4 * * *"`):** Запуск по астрономическому времени UTC (`минута час день месяц день_недели`). Задача запускается один раз в минуту совпадения.

Первый запуск — через интервал после старта мастера, а не на старте. Модулю, которому надо
что-то сделать при подъёме, нужен `#[init]`: он выполняется один раз и уже с выданными
возможностями.

Через перезапуск ничего не помнится: «раз в час» значит раз в час работы. Мастер,
перезапускаемый каждые двадцать минут, часовую задачу не выполнит никогда — если для вашего
модуля это важно, держите время последнего запуска у себя в хранилище и сверяйтесь.

## Сколько это стоит

Задаче даётся тридцать секунд — вшестеро больше, чем обработчику события: она не стоит на
пути живого запроса и может сходить в сеть или обойти свои таблицы.

Два запуска одной задачи не пересекаются. Воркер модуля обрабатывает по одному вызову за
раз, поэтому задача, ещё работающая к следующему тику, просто задержит его, а не запустится
дважды.

Падающая задача считается модулю ровно так же, как падающий обработчик события: десять
сбоев за пять минут — и модуль выключается. Задача, которая падает раз в час, доберётся до
этого нескоро, и так и задумано: предохранитель стоит на модули, сыплющиеся в цикле, а не
на те, что ошибаются изредка.

## Чего здесь нет

Нет способа запустить задачу по требованию, пропустить очередную или спросить, когда она
отработала в последний раз. Если это нужно вашему модулю — ему нужно своё состояние и своя
ручка, и тогда задача становится просто тем, что их зовёт.

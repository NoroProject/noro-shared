```bash
cargo install cargo-noro
```

Ставится подкомандой cargo. Любая команда ниже работает из любого места внутри модуля:
инструмент поднимается вверх, пока не найдёт `manifest.toml`, — так же, как `cargo build`
ищет `Cargo.toml`.

## `cargo noro new <id>`

Создаёт модуль: манифест, ящик, локали, мини-апп и `src/lib.rs` с рабочим примером каждого
вида объявления — или вовсе без них, с `--bare`.

| Флаг | Что делает |
|---|---|
| `--ui vue` | компонент Vue, который панель монтирует внутри себя (по умолчанию) |
| `--ui none` | без экрана — только события, ручки и задачи |
| `--bare` | пустой `impl Module {}` вместо примеров |
| `--name "My Module"` | отображаемое имя; иначе выводится из идентификатора |
| `--path DIR` | куда положить; иначе каталог с именем модуля |

`--bare` — для случая, когда вы знаете, что пишете. Примеры читаются быстро, но в вашем
проекте они чужой код: их сначала опознают как чужие, а потом удаляют. Каркас несёт
комментарий с перечнем пяти атрибутов и ссылку на каталог, и больше ничего; экран, если вы
его попросили, не зовёт ни одной ручки — звать нечего.

Идентификатор спрашивают один раз, потому что он разъезжается по четырём местам, которые
обязаны совпадать: имя ящика, `id` в манифесте, префикс каждого ключа локали и пакет
мини-аппа. Менять его потом — работа во всех четырёх.

Шаблон вшит в двоичный файл, а не скачивается: команда работает без сети и даёт ровно то,
что эта версия инструмента умеет проверить и собрать.

## `cargo noro check`

Читает манифест **теми же типами, что и мастер** — `noro-module-abi`, а не копией, — и
говорит, что отвергнут при установке:

- действие возможности, которого не существует (`players = ["banish"]`), со списком тех, что есть
- ключ локали без префикса `mod-<id>-`
- ключ, на который манифест ссылается, а ни один `.ftl` его не определяет
- узел права вне `noro.module.<id>.`
- миграции без номера в начале имени или две с одним номером
- версия ABI, которую этот мастер не примет

Ничего из этого не требует работающего мастера и ни одно не является второй реализацией
правил. Ценность во времени: без этой команды всё перечисленное — ошибки установки, то есть
находятся после сборки, загрузки и клика.

## `cargo noro key new` · `key show`

Заводит ключ, которым подписываются пакеты, и показывает его открытую часть.

Подпись здесь не про то, что мастер доверяет незнакомцу: владелец кладёт файл сам, и файл,
который он положил, ему уже знаком. Она про **обновление**: пакет с тем же идентификатором
и другим ключом — это другой автор, и мастер его отвергает, а не принимает молча. У модуля
уже есть выданные возможности, своя схема и данные его игроков.

Ключ ложится в `~/.config/noro/keys/<id>.key`, а не рядом с проектом: там он уехал бы в git
с первым же `git add .`, и на этом подпись бы кончилась. Сохраните копию отдельно — без неё
выпустить обновление этого модуля можно будет, только сняв его и поставив заново.

## `cargo noro build [--debug]`

Сначала мини-апп — его ошибки читаются легче, а wasm собирается дольше, — потом wasm, потом
`wasm-opt -Oz`, если он установлен. Отсутствие `wasm-opt` — строка в выводе, а не ошибка:
пакет просто будет больше.

`--debug` пропускает release-профиль и оптимизатор. Собирается быстрее, весит примерно
вчетверо больше, и выпускать это не надо.

## `cargo noro package [--debug] [--sign]`

Собрать и упаковать в `dist/<id>.noromod`. Печатает размер и sha256, по которому мастер
будет узнавать пакет.

`--sign` добавляет `signature.toml`. Подписываются **записи** — каждое имя и его байты,
отсортированные, — а не архив: zip несёт своё время, свой порядок и свой способ сжатия, так
что две одинаковые сборки отличались бы, и вы увидели бы «ключ не тот» после обычной
пересборки.

Неподписанный пакет ставится нормально. Перейти от неподписанного к подписанному можно —
вы завели ключ. Обратно нельзя: так выглядела бы подмена, и отличить её от забытого ключа
нечем.

Архив пишется своим кодом, а не вызовом `zip`: тот стоит не везде, а на macOS кладёт внутрь
записи `__MACOSX`, из-за которых мастер видит файлы, которых автор не клал. Записи
отсортированы, поэтому две сборки одних и тех же исходников дают один хеш.

## `cargo noro dev`

Пересобирает на каждое сохранение — для [режима разработки](../../guides/dev-mode/)
мастера. Неудачная сборка печатает ошибку и продолжает следить: вы исправляете опечатку и
сохраняете снова, а не запускаете цикл заново.

## `cargo noro gen-types [-o FILE]`

Генерирует TypeScript-определения интерфейсов из структур Rust вашего модуля (структуры с `Serialize` или `Deserialize`).

| Флаг | Назначение |
|---|---|
| `-o`, `--output` | Путь к генерируемому файлу. По умолчанию `ui/types/module-generated.d.ts` (или `types/module-generated.d.ts`). |

Обеспечивает сквозную типизацию между веб-интерфейсом (мини-аппом) и серверными ручками модуля.
